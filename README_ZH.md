# NightCoop Hub — Windows 一键部署工具

<p align="center">
  **让 Windows 用户更轻松地搭建自己的 NightCoop Hub**
</p>

一个面向 Windows x64 用户的 NightCoop Hub 便携部署封装。

无需自行安装 Rust、Visual Studio、Docker 或编译环境。下载并解压后，即可通过批处理脚本完成基础配置、启动 Hub 和管理密钥。

本项目希望降低 NightCoop Hub 的部署门槛，让更多《赛博朋克 2077》（Cyberpunk 2077）NightCoop 玩家能够搭建自己的联机 Hub，与朋友一起畅玩夜之城。

## 项目介绍

NightCoop Hub 是 NightCoop 联机系统使用的 Hub 服务端程序。

原始 Hub 项目提供源码及部署指南，用户可以通过 Docker 或自行编译等方式部署服务端。

本项目在此基础上提供 Windows 便携部署封装，将预编译的 Hub 程序与常用管理脚本整合在一起，使普通 Windows 用户无需自行配置编译环境即可部署自己的 Hub。

你可以：

- 在自己的 Windows 电脑上运行 Hub。
- 将 Hub 部署在 Windows Server 云服务器或 VPS 上。
- 与朋友共享 Hub 连接信息。
- 根据需要调整服务器名称、端口和客户端数量等参数。
- 为不同的朋友或玩家群体搭建独立的 Hub。

**注意：本项目部署的是 NightCoop Hub，而不是 Cyberpunk 2077 游戏服务器。** 游戏世界仍由 NightCoop 联机系统中的主机玩家提供。

## 功能特点

- **Windows 一键启动：** 双击批处理文件即可启动 Hub。
- **无需自行编译：** 提供预编译的 Windows x64 可执行程序。
- **独立密钥：** 每个部署实例使用自己的签名密钥。
- **配置管理：** 通过配置文件调整支持的服务器参数。
- **日志记录：** 保存运行日志，方便排查问题。
- **密钥备份：** 提供独立的密钥备份脚本。
- **防火墙配置：** 提供自动开放默认 UDP 端口的脚本。

## 运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / Windows 11 / Windows Server |
| 系统架构 | x64 |
| 网络 | 可被客户端访问的网络环境 |
| 权限 | 配置 Windows 防火墙时需要管理员权限 |
| 开发环境 | 无需安装 Rust、Visual Studio 或 Docker |

如果部署在云服务器上，还需要在云服务商的安全组中开放对应 UDP 端口。

## 下载与安装

### 1. 下载程序

前往本项目 GitHub 的 Releases 页面，下载最新的 Windows 便携版压缩包。

解压到一个独立目录，例如：

```text
D:\NightCoop-Hub\
```

建议不要将程序放在 Windows 系统目录、临时目录或其他受保护的目录中。

### 2. 目录结构

解压后的目录结构如下：

```text
NightCoop-Hub/
│
├─ nightcoop_hub.exe
│
├─ 启动服务器.bat
├─ 开放防火墙端口.bat
├─ 备份密钥.bat
│
├─ config.json
│
├─ data/
│   └─ （保存本机密钥及数据）
│
└─ logs/
    └─ （保存运行日志）
```

实际文件以对应 Release 发布包为准。

请不要随意删除、移动或修改程序目录中的文件。

## 首次启动

### 第一步：开放 Windows 防火墙端口

双击：

```text
开放防火墙端口.bat
```

根据 Windows 提示允许管理员权限。

该脚本用于添加默认 Hub UDP 端口的 Windows 防火墙入站规则。

如果使用云服务器，还需要在云平台控制台中开放相同的 UDP 端口。

### 第二步：启动 Hub

双击：

```text
启动服务器.bat
```

首次运行时，程序会按照部署包的配置流程初始化所需数据及密钥。

启动成功后，控制台会显示服务器运行信息。

请留意：

- Hub 名称
- 监听端口
- Hub 指纹（Fingerprint）
- 服务器启动状态

请保存 Hub 指纹及连接地址，后续需要提供给其他玩家。

### 第三步：保持服务器运行

Hub 启动后，请保持控制台窗口运行。

关闭窗口或终止进程可能导致 Hub 离线，其他玩家将无法通过该 Hub 建立连接。

如需停止服务器，建议在控制台中使用 `Ctrl + C`，等待程序正常退出。

## 服务器配置

打开程序目录中的：

```text
config.json
```

根据文件中提供的配置项及注释修改参数。

常见配置内容包括：

| 配置项目 | 说明 |
|---|---|
| Hub 名称 | 玩家识别服务器时显示的名称 |
| 监听端口 | Hub 使用的 UDP 端口 |
| Shards / Threads | 服务端分片或线程相关配置 |
| 最大客户端数量 | 限制允许接入的客户端数量 |
| Region | 服务器区域标识 |

修改配置前，建议先停止 Hub。

修改完成后，重新运行 `启动服务器.bat` 即可使新配置生效。

**重要：请以当前版本的 `config.json` 为准。不要随意添加未经程序支持的参数。**

如果修改了端口或线程数量，请同步检查 Windows 防火墙及云服务器安全组规则。

## 客户端连接

### 1. 安装 NightCoop 客户端

所有参与联机的玩家都需要安装 NightCoop 客户端模组及其依赖。

请确保：

- 游戏版本符合 NightCoop 当前版本要求。
- 所有参与同一联机活动的玩家使用兼容的 NightCoop 构建版本。
- 客户端安装路径正确。
- 游戏主菜单中可以正常看到 Co-op 联机选项。

客户端安装方法请参考：

https://nightcoop.net/docs.html#install

### 2. 获取 Hub 连接信息

服务器管理员需要提供：

1. Hub 地址。
2. Hub 密钥指纹（Fingerprint）。

连接地址格式示例：

```text
hub.example.org#K3QF-9X2M-TV7A-0D4R
```

也可以使用 IP 地址：

```text
203.0.113.7#K3QF-9X2M-TV7A-0D4R
```

如果使用非默认端口，格式示例：

```text
hub.example.org:47900#K3QF-9X2M-TV7A-0D4R
```

以上均为格式示例，请替换成自己的服务器地址和指纹。

### 3. 添加自定义 Hub

在游戏中打开：

```text
Co-op → Server → Add an own server
```

输入或粘贴管理员提供的地址和指纹，然后保存。

连接成功后，游戏会显示服务器状态及验证信息。

### 4. 邀请其他玩家

主机玩家创建联机房间后，可以使用 NightCoop 提供的 Copy invite 功能复制邀请信息。

邀请信息通常包含：

- 联机房间代码。
- Hub 地址。
- Hub 指纹。

其他玩家可以将邀请信息粘贴到 Join by code 中加入房间。

更多客户端连接说明：

https://nightcoop.net/docs.html#install

## 密钥管理

每个 Hub 都应该拥有独立的签名密钥。

本项目的设计目标是让每个用户在自己的部署目录中使用独立密钥，而不是共享其他人的服务器身份。

### 密钥存放位置

本部署包使用独立数据目录：

```text
data/
```

该目录用于保存本机密钥及相关数据。

请不要随意删除、覆盖或移动已经生成的密钥文件。

### 备份密钥

双击：

```text
备份密钥.bat
```

根据脚本提示完成备份。

建议将密钥备份到其他安全位置，例如加密 U 盘或受控的私有存储空间。

### 为什么必须备份？

Hub 的密钥与服务器身份有关。

如果删除或丢失原有密钥，重新生成密钥可能导致 Hub 身份发生变化。

客户端可能需要重新验证服务器，并更新保存的指纹。

因此：

- 不要随意重新生成密钥。
- 不要将密钥上传到 GitHub。
- 不要通过群聊或公开网盘分享密钥。
- 不要让多个独立 Hub 共用同一份私钥。

**Hub 指纹可以分享给玩家，签名私钥绝对不能分享。**

## 网络与防火墙配置

### 默认端口

NightCoop Hub 默认使用：

```text
47800 / UDP
```

请确保以下两处都允许对应的 UDP 流量：

**Windows 防火墙**

使用项目提供的：

```text
开放防火墙端口.bat
```

**云服务器安全组**

在云服务商控制台添加入站规则：

| 协议 | 端口 | 方向 |
|---|---|---|
| UDP | 47800 | 入站 |

### Shards / Threads 相关端口

根据 NightCoop 官方指南，线程相关端口通常还涉及：

```text
47810+
```

如果线程端口未开放，创建联机会出现额外等待时间，官方文档提到可能延迟约 5–6 秒。

通常仍然可以进行联机，但建议服务器管理员根据实际线程配置及服务端监听情况开放所需的额外 UDP 端口。

官方说明：

https://nightcoop.net/docs.html#install

### 家用电脑部署

如果在家用电脑上部署，需要注意：

- 电脑必须保持开机。
- Hub 程序必须持续运行。
- 路由器可能需要配置 UDP 端口转发。
- 如果运营商使用 CGNAT，普通端口转发可能无法实现公网访问。

### 云服务器部署

如果在 Windows 云服务器上部署，建议：

- 使用 Windows Server x64。
- 使用固定公网 IP 或稳定域名。
- 只开放必要的 UDP 端口。
- 定期备份密钥。
- 定期检查日志及磁盘空间。

## 日志与故障排查

日志目录：

```text
logs/
```

如果服务器无法启动或玩家无法连接，建议检查：

1. 控制台是否出现错误信息。
2. `logs` 目录中是否生成日志。
3. 配置文件是否被错误修改。
4. UDP 监听端口是否被其他程序占用。
5. Windows 防火墙是否允许程序通信。
6. 云服务器安全组是否开放对应 UDP 端口。
7. 客户端使用的 Hub 地址和指纹是否正确。

### 常见错误

| 提示或现象 | 可能原因 | 处理方法 |
|---|---|---|
| 服务器无法启动 | 配置错误或程序文件缺失 | 检查配置和程序目录 |
| Server does not answer | Hub 未运行或 UDP 端口未开放 | 检查服务端及防火墙 |
| Server is not found | 域名无法解析 | 检查域名或改用公网 IP |
| Server failed the key check | 指纹与服务器密钥不匹配 | 向管理员重新获取地址及指纹 |
| 创建联机房间需要额外等待 | 线程相关 UDP 端口未开放 | 检查 47810+ 端口 |
| 重启后服务器身份发生变化 | 原密钥丢失或更换 | 恢复原密钥备份 |

### 客户端日志

如果问题发生在游戏客户端，也可以检查 NightCoop 和 RED4ext 日志。

官方文档提供了以下日志位置：

```text
Cyberpunk 2077\red4ext\logs
```

以及：

```text
Cyberpunk 2077\red4ext\plugins\NightCoop\logs
```

如需反馈 NightCoop 客户端问题，建议记录发生时间、操作过程及自己是主机还是加入者，并按照官方指南提交日志。

## 安全建议

请务必遵守以下原则：

1. **不要公开分享私钥。** 私钥是服务器身份的重要组成部分。
2. **不要将私钥提交到 GitHub。** 包括公开仓库和不受控的备份仓库。
3. **不要公开分享包含私钥的完整服务器目录。**
4. **不要将个人公网 IP、访问凭据或敏感日志提交到公开仓库。**
5. **不要随意开放不需要的网络端口。**
6. **建议定期备份密钥和配置文件。**
7. **如果怀疑密钥泄露，请按照上游项目支持的密钥管理方式进行处理。**
